Trail — Approach: M1 vector-add → sm_120 inference kernels
Human-first kernel design · correctness gate → roofline → iterate · informed by the engine landscape (vLLM / SGLang / llama.cpp / FlashInfer) and Qwen3.8-27B sm_120 case study

The method (every kernel)

  • • Human designs first, AI research/review second (§8 rule)
  • • Correctness gate: differential test + sanitizer
  • • Roofline gate: GB/s vs 1.79 TB/s peak — >100% means the measurement is broken
  • • Same protocol KernelBench / FlashInfer-Bench use for AI-generated kernels

Experiment ladder (post-M1)

  • • float4 loads — 4x fewer instructions, same principle as q4_0 KV cache being faster than f16 in the Qwen 5090 sweeps
  • • Fused chain — 3-pass → 1-pass memory traffic; fusion pays most at 1.79 TB/s
  • • Grid-size sweep — blocks = 1×..12× SM count (170 SMs)
  • • Graphs + dynamic shapes — extends E0001 toward FlashInfer's frontier

Calibration targets (RTX 5090)

  • • Kernel launch: 4.5 µs plain / 0.79 µs graphed (E0001, ours)
  • • Vector-add roofline: ~1.79 TB/s → expect 64–90% of peak
  • • Qwen3.8-27B decode: 69 → 152 tok/s from stack choices alone
  • • llama.cpp speed-of-light rule: ~80% of theoretical is excellent
